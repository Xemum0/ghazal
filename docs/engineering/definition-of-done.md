# Definition of done

> Work is done only when every applicable line below is true **and** the evidence is in the final message. "It compiles" and "the types pass" are not done. Sources: ADR 0025 (QA loop), 0024 (handoff), 0029 (verify), and the ADRs cited per line. How to test: [testing.md](testing.md). How agents work: [agentic-workflow.md](agentic-workflow.md).

## Interim definition of done (until the foundation PR lands; this week's version)

Checklists A to E below describe the target state: `pnpm verify`, `pnpm shots`, `pnpm a11y`, `pnpm specs:check`, Biome and Stylelint, `design/specs/**`, the read-only reviewer subagents, the Stop hook and `requests.md` mostly do not exist yet (and local http screenshots are forbidden until `tools/ports.mjs` exists: [agentic-workflow.md](agentic-workflow.md) section 7). Do not fake any of them. Work is done today when:

- [ ] Every requirement ID cited exists: `node -e "const m=new Map(require('./docs/product/feature-matrix.json').map(x=>[x.id,x]));for(const id of process.argv.slice(1))console.log(id,m.has(id)?m.get(id).designScope:'MISSING')" ID1 ID2` from the project root (design work needs `designScope` true).
- [ ] Copy is checked against `docs/design/content-guidelines.md` and glossary section 9; both languages present; Arabic plurals follow ADR 0013 D7.
- [ ] Money, dates and phones match `docs/design/seed-rulebook.md` (one value per fact, arithmetic reconciles).
- [ ] Any static exploration was screenshotted from a `file://` page: `node design/scripts/snap.mjs <file.html> <out.png> --lang ar` and again with `--lang en`, and the Arabic PNG was actually opened with Read.
- [ ] JSON edited by you validates (`node -e "JSON.parse(require('fs').readFileSync('<file>'))"`); the matrix `.md` and `.json` twins still match.
- [ ] No edits outside the paths the task owns; accepted ADRs respected; new ideas appended to `docs/product/open-questions.md`.
- [ ] The final message carries the evidence block with every gate that could not run listed under `Not verified` as "not run (foundation PR)".

Pick the checklist for the work: **A** applies to everything; then **B** a design screen, **C** a Flutter feature, **D** an API endpoint, **E** a token, shared component, fixture or document. A line that truly does not apply is struck with a reason, not silently skipped.

## A. Every change

- [ ] Traces to requirement IDs from `docs/product/feature-matrix.json` (each exists, `designScope` true for design work) or to a named ADR. Nothing invented: a new idea goes to `docs/product/open-questions.md` (append with `>>`), not into the design or code.
- [ ] Respects accepted ADRs. A needed change to one is a new ADR via `node tools/new-adr.mjs`, not a quiet deviation.
- [ ] Edited only the paths the task owns. A needed token, shared component or dependency is one appended line in `docs/engineering/requests.md`, not an edit.
- [ ] `pnpm verify <area>` passes (design, flutter or api; `all` if the change spans areas). The Stop hook's fast gate alone is not enough.
- [ ] Both languages exist and were looked at. No hardcoded user-facing string, colour, spacing, radius, duration or easing outside the token and i18n layers.
- [ ] Money, dates, numbers and phones go through the shared formatter; fixtures hold fils and enums only (conventions section 6).
- [ ] No secret, key, real phone number, real brand, real person, `.env*` or archive touched or created. The pirated `BookingSaaS v2.3 Nulled.rar` was not opened.
- [ ] Generated files were regenerated by their generator, not edited (the list is `docs/engineering/generated-files.md`, which the integrator creates in the foundation PR).
- [ ] No git commit, push or tag unless the owner asked.
- [ ] Final message includes the evidence block at the end of this file.

## B. Design screen (prototype)

### B1. Trace and spec
- [ ] Screen inventory ID (`CL-...` or `HL-...`) and spec id (`<app>.<group>.<slug>`) recorded; the spec lists every requirement ID the screen covers and the inventory `states` it implements.
- [ ] `design/specs/screens/<app>/<group>/<slug>.spec.json` validates against `screen.schema.json`: route, components, fixture, states (loading, empty, error, offline plus the inventory-specific ones), scroll behaviour in dp, safe areas, ARB keys, `analytics:` events from the registry, `permission` key for hotel screens, `qa` filled at the end.
- [ ] A new component has its own `components/<Name>.spec.json` and is built in `design/src/system/` by the system owner; screens only compose. `pnpm specs:check` passes (schema, IDs exist, token paths resolve, ARB keys exist in en and ar, every anchor exists in the DOM).
- [ ] Every component root has `data-gz`, every measured node `data-gz-id`.
- [ ] Priority respected: a `core` screen is fully wired and polished; a `supporting` screen recombines shared sheets, lists and forms to design-system standard.

### B2. Copy and Kuwait rules (each line is checkable by eye)
- [ ] Arabic written, not translated: possessive `كم`, verbal-noun CTAs, gender-neutral, guests are `ضيف / ضيوف` with CLDR plural categories (`350 ضيفًا`, `300 ضيف`), no banned term (the full list is glossary section 9 and `docs/design/content-guidelines.md`; for example `ليلة` plus a weekday, `بالرفاء والبنين`, `حيّاك الله`, `حريمي`, `اختر / اختاري`, `مدعو / مدعوات`, `عزيزي العميل`, dialect words in labels, religious phrases in payment, error or discount text). English is British, calm, precise. No exclamation marks, no emoji, no urgency words (`Hurry`, `Only N left`, `Don't miss out`), no `Welcome back`, no lorem ipsum.
- [ ] Arabic strings are marked unreviewed in the catalogue until a native Kuwaiti reader has seen them (OQ-L-06).
- [ ] Money: Western digits; AR `د.ك` after an LTR-isolated number, EN `KD`; `KWD` only on invoices, receipts, bank and payout settings; browse precision vs exact three decimals as per ADR 0010; one precision per list; a price always shows its unit and guest basis; no bare `From KD X`; no VAT lines; `No booking fee` absent (OQ-B-15).
- [ ] Dates: weekday plus date everywhere; no numeric-only date; 12-hour Asia/Kuwait time; relative words only `Today` and `Tomorrow`; Sunday-first custom calendar with the Thu-Sat band at the inline-end edge; Hijri only as a muted Arabic line on date confirmations and booking summaries and as approximate occasion markers.
- [ ] Phones display `+965 5000 00NN` as an LTR isolate and are not tappable; IBAN, references, coupon codes are LTR isolates.
- [ ] Areas, venue names, prices and capacities come from the roster and tiers in `docs/design/seed-rulebook.md`; no area outside the list; venue names at most 24 characters on a card.
- [ ] Imagery: empty rooms and details only; no identifiable face, silhouette, alcohol, royal or state emblem, mosque or real landmark; avatars are one-letter monograms; section badges are text chips; every image has bilingual alt text.

### B3. Product patterns (check those the screen touches)
- [ ] Booking CTA reads `Request to book` (never `Book now`) unless the hall is instant-eligible (`Pay deposit KD {amount}`, `Instant` only on eligible halls). Nothing is charged or held at request (ADR 0001).
- [ ] Pending shows an absolute `Expected reply by ...`, no ticking timer. A live countdown appears only in the final 60 minutes of a pay window and during the 10-minute instant hold.
- [ ] Review shows the itemised price, the schedule line (Today, On approval, Balance due, Free cancellation until), consent to policy and terms, a coupon field; no fee appears after Review.
- [ ] Status chips use icon plus label and the nine statuses of ADR 0003; one Booking detail with variants; the Booking Thread uses absolute times and at most two faint future nodes.
- [ ] Hall switcher, session chips and audience chips appear only when there is a real choice; `Mixed` is last and never the default (ADR 0002).
- [ ] Government halls: no Ghazal checkout, deposit, instant tag, availability claim or reviews; Compare shows `Official channel`.
- [ ] Guest gating per ADR 0007 D8: open browse, soft gate before step 4, hard gate sheet that resumes the exact intent; a draft is never lost.
- [ ] Compare tray appears only on Home, Results and Saved after the first add, collapses to a pill, never nags; the fourth add opens `Replace which one?`.
- [ ] Hotel: Accept in two taps with an 8-second Undo; Decline three taps with a required reason; no swipe actions anywhere; SLA state always has text; roles hide, never lock; offline disables money and calendar actions in place with a reason.
- [ ] Open owner decisions (cancellation tiers, deposit percentage, commission, credit caps, occasion chip, share links, `Notify me if this date opens`) are visibly flagged as placeholders in the spec.

### B4. States
- [ ] Loading (static skeleton, no shimmer), empty, error (calm, blameless), offline (cached with `Updated {time}`) exist for every key surface. Anything that moves money or commits a decision is never queued and is disabled in place with a plain reason.

### B5. Visual system
- [ ] Only token values; Stylelint clean (Flutter-subset CSS, logical properties, no banned effects, waivers carry a reason).
- [ ] 4-pt grid, one gutter token, one primary action per screen, hierarchy readable at a glance, frame 390 x 844 and fluid at 360 and 430.
- [ ] Three brand colours plus the small functional set; gold is never text; gold is never the only boundary of an input or selected state; labels on gold use the dark label ink.
- [ ] Motion uses tokens (120, 200, 320, 480 ms, success 640 ms once per flow, thread draw-on 320 ms); animates transform and opacity only; nothing loops; money and counts never roll; reduced motion keeps all information.

### B6. RTL (ADR 0014 section 10, every screen, both languages, 360/390/430)
- [ ] Icon registry respected (chevrons, send, back mirror; play, check, plus, clock, phone, map pin, heart do not); tabs, stepper, slider, progress, star fill and carousels mirror; photos, maps, logos do not.
- [ ] Numbers, prices, phones and dates are isolated and unscrambled; the currency token sits visually left of the number in both languages.
- [ ] Arabic type per ADR 0016 (caption 13/20, small 15/24, body 17/28); no letter-spacing, italic, uppercase or justified Arabic; no Latin and Arabic baseline clash; no clipped text at 360 with 200% text scale.
- [ ] Arabic drawn through the real components, never by flipping an English frame.

### B7. Accessibility (WCAG 2.2 AA)
- [ ] Contrast comes from `a11y-pairs.json` tokens; status never relies on colour alone; targets at least 44 x 44 (48 for primary controls); visible 2 px focus ring; logical focus order in RTL; `prefers-reduced-motion` honoured.
- [ ] `pnpm a11y` (axe per route and locale) has no serious or critical finding; every interactive element has an accessible name from the i18n layer; status changes are announced.

### B8. Evidence and handoff
- [ ] `pnpm shots --screen <id>` run on an identity-checked URL; the contact sheet and **every Arabic PNG were Read at full size**. Reviewers `design-qa`, `rtl-reviewer`, `a11y-auditor` ran; findings fixed in at most three iterations; the rest escalated.
- [ ] For the eight hero screens (ADR 0024 D10; `HL-CALN-01` joins once frozen): `pnpm -F design redlines --screen <id>` exported and the `handoff-screen` packet produced (spec, six screenshots, redlines, tokens used, ARB keys, fixture, owned Flutter files, tests to add).
- [ ] Spec `qa` field updated with the run and status.

## C. Flutter feature

### C1. Prerequisites (do not start without them)
- [ ] The screen specs are frozen with `qa` recorded; tokens are generated; every component the feature needs exists in `ghazal_ui` or is requested; the fixture exists in `packages/contracts/fixtures`; the API operation is in `openapi.json` or served by Prism; ARB keys are merged. See [apps/README.md](../../apps/README.md).

### C2. Implementation
- [ ] Layering holds: presentation, application (notifier), domain (entity, repository interface), data (implementation, DTO, mapper). Generated DTOs never reach a widget. No import of another feature's `presentation/` or `data/`. Routes live in `<feature>_routes.dart`; `app_router.dart` was not edited.
- [ ] `tools/check-dart-rules.sh` clean: no `package:flutter/material.dart` or `cupertino.dart`, no `Color(0x` or `Colors.`, no physical left or right, no string literal in `Text(`, no Arabic letter-spacing.
- [ ] Every string from `AppL10n`; every number, price, date, time and phone from `GzFormat`; time from the clock provider; digits normalised on every numeric input.
- [ ] States present: loading, empty, error, offline. Booking creation, payment, accept, decline, block and cancel are never queued offline and never auto-retried; a user retry reuses the same `Idempotency-Key`.
- [ ] Guest gate: `AUTH_REQUIRED` and `PHONE_VERIFICATION_REQUIRED` store a `GuestIntent` and resume the exact screen, selections and scroll after sign-in.
- [ ] Notification landings rebuild the stack (tab root, parent, target) per ADR 0007 D11 (client) and 0008 D13 (hotel). OS notification permission is requested after the first save or first booking request, never at launch.
- [ ] Hotel only: the role's permission keys come from `/v1/me`; forbidden objects show `You do not have access. Ask your manager.`; the new-request push is time-sensitive with the badge set to the pending count.
- [ ] Analytics events fire through the `Analytics` interface with names from `events.json`; no PII in any property.
- [ ] Accessibility: semantic labels from the ARB, `ExcludeSemantics` on decoration, `SemanticsService.announce` on status changes, targets at least 44 dp, no clipping at 200% text scale in Arabic at 360.
- [ ] Motion tokens and haptics only; reduced motion mapped from `MediaQuery.disableAnimationsOf`.
- [ ] No secret in the app; only public config through `--dart-define-from-file`; `GZ_LOCALE` works in non-prod flavors only; iOS floor 15.0 and `minSdk` 26 unchanged.

### C3. Tests and evidence
- [ ] Unit: mappers against shared fixtures, notifiers against fake repositories, retry and gate logic. Coverage at least 70% on logic packages.
- [ ] Goldens per the matrix in testing.md section 5 (Arabic and English, both text scales, default and stress fixtures); the diff PNGs were Read before any update.
- [ ] Hero screens: parity test within 1 dp against the redlines (`handoff-checker` lists no delta above 1 dp).
- [ ] Core flows touched have an `integration_test` case; performance budgets hold for Home and Search (`home_ttfmc` at most 2.0 s p75, scroll p90 under 8 ms).
- [ ] `pnpm verify flutter` tail pasted; one Arabic simulator or emulator screenshot attached for UI work.

## D. API endpoint

- [ ] Contract first: Zod request and response schemas in `packages/contracts` with `.meta({ id })`; every operation uses `@Api({ summary, auth, permissions, params, query, body, responses, errors })`; `openapi.json` re-emitted and committed; Spectral clean; oasdiff reports no unplanned breaking change; TS and Dart clients regenerated.
- [ ] Authorisation: permission key declared and enforced by the guard; tenant guard scopes by venue; the generated tenancy test covers the route; `X-Venue-Id` is validated against membership, never trusted. Bank info, refunds and staff changes require server-enforced step-up.
- [ ] Money and time: `*_fils BIGINT`, wire `{ fils, currency }`, commission in basis points with the shared rounding function, no floats; `event_date` is a DATE in Asia/Kuwait; the clock is injected; the venue business day is 06:00 to 06:00.
- [ ] Idempotency: every POST that moves money or a slot requires `Idempotency-Key`; a replay test exists.
- [ ] Booking state: transitions go through the state machine with a version check, append a `booking_events` row, claim slots only on approval, instant checkout, confirmation or a venue block (through the exclusion constraint), and dispatch notifications through the queue. Accept honours the 8-second undo (deferred dispatch).
- [ ] Payments: webhook verifies the signature, writes the inbox, re-queries `GetPaymentStatus` before any change, and is idempotent; no card data; secrets only from Secret Manager.
- [ ] Errors: RFC 9457 problem+json with a stable `code` registered in `packages/contracts`; no user-facing prose in bodies; the client ARB key `commonError...` exists in both languages; push, WhatsApp, email and PDF text comes from `packages/i18n/messages/server` in the user's locale.
- [ ] Input hygiene: Arabic-Indic and Persian digits normalised on every numeric, phone, OTP and amount field; rate limit configured; no PII, chat text or card data in logs or analytics.
- [ ] Audit: state changes write through the audit trigger with the actor set by `SET LOCAL app.actor_id`.
- [ ] Database: forward-only migration with timestamp name, hand-written SQL for constraints and PostGIS, expand then contract, one migration per PR, indexes for the query, `EXPLAIN` checked for hot paths. Public GETs carry ETag and Cache-Control; `GET /v1/home` stays at most 30 KB gzip.
- [ ] Tests: unit plus Testcontainers integration; the mandatory suite for the area (double booking, tenancy, webhooks, idempotency, money, state machine) extended; coverage at least 70% on the domain layer.
- [ ] Documentation: the module README states its states, events and open questions; server analytics events are registered. `pnpm verify api` tail pasted.

## E. Token, shared component, fixture, document

- **Token**: has a reason in `$extensions.ghazal.reason`; goes through the `add-token` skill; `pnpm tokens:check` passes including the contrast pairs; after design freeze it also needs an ADR and a STATUS broadcast.
- **Shared component**: spec JSON, Flutter widget name `Gz<Name>`, states, RTL mirror and no-mirror lists, ARB keys, a `@Preview` and a golden once Flutter exists.
- **Fixture or seed content**: follows `docs/design/seed-rulebook.md` (fixed NOW, roster ids, patterned phones, prices that reconcile: 350 x 52 = 18,200.000; deposit 5,460.000; balance 12,740.000); the same file feeds the prototype and Flutter tests; the shared booking reference reads identically in both apps.
- **Document**: concrete, Kuwait-specific, cites requirement IDs and ADRs, no filler sections; links resolve; an assumption is recorded as an open question, not stated as fact.

## Not done, and done but flagged

Not done: any gate failing; Arabic never looked at; a screen without requirement IDs; the Stop hook bypassed; a verify run on the wrong server (a PNG of another project's app); an edit outside owned paths.

Done but flagged: owner decisions still open (OQ-B-xx, OQ-L-xx, OQ-T-xx) may remain placeholders if they are configuration, flagged in the spec or the code comment, and listed in the final message. Done never means the owner accepted a pending ADR (0005, 0006, 0015, 0019, 0020 are proposed).
