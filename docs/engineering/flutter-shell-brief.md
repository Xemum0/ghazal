## The contract (names are fixed: every agent codes against them)
Package `packages/ghazal_app_kit` (barrels already exist: `src/nav/nav.dart` K1; `src/data/data.dart`, `src/session/session.dart`, `src/state_views/state_views.dart`, `src/bootstrap/bootstrap.dart`, `src/demo/demo.dart` K2). Dart names below are the public API; add to them freely, never rename them.

**Session and gate (K2; create the TYPES first, within your first 15 minutes, because K1's router reads them)**
```dart
enum GateReason { sendRequest, voucher, visit, chat, review, planner, quote, save }   // web GateReason, ADR 0033
sealed class Session { const Session(); bool get isSignedIn; }
final class GuestSession extends Session ...                       // browsing, no token
final class ClientSession extends Session { final AuthUser user; ...}   // signed-in client (user: id, name, phone, monogram)
final class PartnerSession extends Session { ... }                 // signed-in partner staff: account type (hotel | provider), staff role, venueId / providerId context
final sessionProvider = NotifierProvider<SessionNotifier, Session>(SessionNotifier.new);
final class GateResume { const GateResume(this.routeName, [this.params = const {}]); }   // where to continue after sign-in
final class GateRequest { const GateRequest(this.reason, this.resume); }
final gateProvider = NotifierProvider<GateNotifier, GateRequest?>(GateNotifier.new);
extension SessionGate on Ref / WidgetRef { bool requireSignIn(GateReason reason, {GateResume? resume}) }
//   true when signed in; false (and the gate sheet opens through gzNavigatorProvider; after sign-in the app continues at `resume`) for a guest
```
**Navigation (K1)**
```dart
final routerProvider = Provider<GoRouter>((ref) => throw UnimplementedError());   // each app root overrides it with its buildAppRouter()
final gzNavigatorProvider = Provider<GzNavigator>(...);                            // GoRouterNavigator over routerProvider; `GzNavigator` is the contract in ghazal_ui (nav group)
Page<T> gzScreenPage<T>(GoRouterState state, Widget child);    Page<T> gzSheetPage<T>(GoRouterState state, Widget child);
```
Route names are the inventory ids (`context.goNamed('CL-DISC-01')`); params travel as `GzParams` (`Map<String, Object?>` of ids, ISO dates, numbers) in `state.extra`. **A screen opened without params shows the hero story entity** (the same default `#/frame/<id>` shows: venue V01, the hero request, Reem's first voucher ...), so the shot harness and the demo can open any screen directly.
**Data (K2)**
`mockBackendProvider` (`Provider<MockBackend?>`, null when `USE_MOCK=false`, overridden at bootstrap with the awaited in-process backend), `apiClientProvider` (`Provider<GzApiClient>`), `repositoriesProvider` (`Provider<RestRepositories>`) and ONE provider per repository typed as the domain interface so tests override with fakes: `authRepositoryProvider`, `homeRepositoryProvider`, `venuesRepositoryProvider`, `vouchersRepositoryProvider`, `requestsRepositoryProvider`, `visitsRepositoryProvider`, `chatRepositoryProvider`, `notificationsRepositoryProvider`, `reviewsRepositoryProvider`, `weddingRepositoryProvider`, `servicesRepositoryProvider`, `plannersRepositoryProvider`, `profileRepositoryProvider`, `supportRepositoryProvider`, `partnerAccountRepositoryProvider`, `partnerRequestsRepositoryProvider`, `partnerBookingsRepositoryProvider`, `partnerCalendarRepositoryProvider`, `partnerVenueRepositoryProvider`, `partnerVisitsRepositoryProvider`, `partnerGrowthRepositoryProvider`, `partnerListingsRepositoryProvider`, `partnerReviewsRepositoryProvider`.
**State views (K2)** `GzAsyncView<T>({required AsyncValue<T> value, required Widget Function(T) data, bool Function(T)? isEmpty, Widget? empty, Widget? loading, VoidCallback? onRetry})` mapping loading / data / empty / error / offline (the `ScreenState` of `ghazal_core`) to the skeleton, the content, `GzEmptyState`, `GzErrorState`, `GzOfflineState` with the cross-fade of the motion list; `ApiProblem` decides error vs offline.

**Persona rule (shot harness, demo, references).** Client screens run as Reem (`reem`, signed in) except CL-ONBD-* and CL-AUTH-* (a first-time `guest`); partner screens run as the hotel manager (`hotel_manager`, venue V01) except HL-ACCS-* (`guest`). It is the same rule `tools/parity/ref-shots.mjs` (`storyFor`) uses to capture the references, so a Flutter shot and its reference show the same person. A `--state` is a mock scenario: `loading` (a request that never completes, pumped for a few frames), `empty`, `error`, `offline`, `expired` (`X-Mock-Scenario`, `MockControl`); `guest` is the guest persona.

## S: app state (after K2; owns `apps/client_app/lib/app/state/**`, `apps/provider_app/lib/app/state/**` and their tests)
Port the prototype store to Riverpod, per app, hand-written `Notifier` / `AsyncNotifier` (no codegen), following `docs/architecture/api-coverage.md`: what the prototype keeps in the browser memory but the real system keeps on the server (vouchers, requests, visits, listings, notifications read state, favourites, wedding profile) is read and written through the repositories; what is a draft or UI memory stays in the app. Client: `favouritesProvider` (server-backed, optimistic, the sign-up nudge after the third heart by a guest, ADR 0007 D10), `compareProvider` (max 3, add / exists / full results, replace, clear), `searchBriefProvider` (the Brief draft with `dateMode`, persisted per device), `weddingProfileProvider`, `bookingDraftProvider` (the web `BookingDraft`: steps package / details / review / sent, extras, personal, voucher binding), `paymentProvider` (the outcome machine idle / processing / success / failed / cancelled / verifying over `createPaymentSession` and `getPaymentState`), `voucherActionsProvider` (checkout, send request R01, cancel R07, confirm R08, ask support credit), `notificationsProvider` (unread count for the tab badge). Partner: `partnerContextProvider` (account type, active venue or provider, staff role), `requestActionsProvider` (accept R03, decline R04, reschedule counter, redeem R11, cancel R10b/R13b) with the 8-second undo (`lastHotelAction`, undo, commit) and the badge counts for the partner tabs. Every provider has the five states where it loads. Tests per provider against the in-process mock (the hero story: Reem requests 14 Jan 2027 and the hotel manager sees it pending in the partner persona; accept, undo, forfeit by the clock). Document the public API in a "App state" section of `docs/engineering/flutter-dev.md` (names, signatures, one usage line each).
