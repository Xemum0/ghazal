## What you build
- One Flutter widget per web component, `GzFoo` in `packages/ghazal_ui/lib/src/<group>/gz_foo.dart` (one public widget per file, helpers private or in `<part>_kit.dart`). Props keep the web names and defaults (`children` string is `label`, `onClick` is `onPressed`, a null callback is disabled). Every state the web doc comment lists (default, pressed, focus, disabled, loading skeleton, no photo, guest-locked, compared, favourite ...) is reachable by a prop, because the gallery shows each one.
- **Data.** Where the web takes a contracts type (`Venue`, `Booking`, `VenueResult`, `CardPrice`, `Voucher` ...) the widget takes the generated model of `package:ghazal_domain/ghazal_domain.dart` (`final class X` in `packages/ghazal_domain/lib/src/models/<tag>.g.dart`; find it with `grep -rn "final class VenueResult" packages/ghazal_domain/lib`). Bilingual values are `LocalizedText` (`.of(context.gz.locale.languageCode)`); money is `MoneyAmount` / integer fils. A widget never fetches, never navigates, never reads a provider: it takes data and callbacks (`onOpen`, `onFavouriteChange` ...).
- **Strings.** The web `defineWords` / `p('English', 'عربي')` pairs and `useT('common')` become ARB. Shared words already exist as `context.gzL10n.commonXxx` (grep `packages/ghazal_ui/lib/l10n/gz_en.arb`); reuse them. Words only your components use go in `packages/ghazal_ui/l10n_src/<your-part>.en.json` and `.ar.json` (same keys and placeholders in both; camelCase keys `ui<Group><Component><Element>`, e.g. `uiClientVenueCardGuests`; ICU plural/select, never a digit in prose; Arabic in the Kuwaiti-market voice of ADR 0013, voucher word «كوبون»). Collect ALL your words first (`grep -n "p('" <file>.tsx`), write both files once, run `pnpm l10n:ui` (one bundle, seconds; it takes the `l10n` lock), and run it again only when a key changes. Never a literal in `Text(`; never a hand-typed number, price or date: `context.gzFormat` (the shared `GzFormat`; see `core/gz_price.dart` for the pattern; the story clock is `context.gzFormat.now()`).
- **Layout and numbers.** Measurements come from the web CSS through the tokens (`GzSpace.sN`, `GzSize`, `GzRadius`, `GzStroke`, `GzElevation`; the web `--gz-space-N` are scale steps, not px). Logical (directional) classes only. When a size, weight or position is not obvious, MEASURE the web instead of guessing from a screenshot: `pnpm probe -- --gallery <page> --within '[data-gz-section="<id>"]' --selector '<css>' --lang ar --depth 3` prints the computed box, font and padding of every match (x y w h in dp, `r` = distance from the right edge). Known trap: inside a web `<button class="gz-reset gz-t-...">` the label renders in the inherited body type (`gzResetLabelStyle`), while the digit size still follows the role (`--gz-num-size`): read the computed `fontSize` of the label AND of the `.gz-num` span. Never hide a geometry mismatch with a padding tweak: find the number.
- **Motion** from `GzMotion` (120 / 200 / 320 / 480 ms, `easeStandard` / `easeEmphasized` / `easeExit`); press is `GzPressable`; draw-on and pops use the core helpers (`GzDrawOnce`, `GzScalePop`, `GzFadeInOnce`); reduced motion through `GzReducedMotion` (no travel, a 120 ms fade). Looping animations only where the web loops.
- **Accessibility**: 44 x 44 targets, Semantics label / value / button / toggled / selected (ONE node per composite card; decoration excluded), visible focus (`GzPressable`), WCAG 2.2 AA by tokens, RTL mirroring per ADR 0014 (mirror set in `GzIcons.mirrorInRtl`; phones, prices, dates stay LTR islands).
- **Performance**: `const` where possible, `RepaintBoundary` around a card that appears in lists, builder-friendly (no `shrinkWrap` lists inside), fixed-aspect photo boxes via `GzPhoto`, no `Opacity` / `BackdropFilter` (the rules script fails them; use alpha colours).
- **Reuse, never rebuild**: core (`GzButton`, `GzChip`, `GzBadge`, `GzStatusPill`, `GzAvatar`, `GzRating`, `GzPrice`, `GzMoney`, `GzDivider`, `GzListRow`, `GzFactChip` ...), brand (`GzThreadKnot`, `GzThreadBead`, `GzMonogram`), inputs, nav, overlays (`GzPhoto`, `GzPager`, `GzSheet`, `GzBanner`, `GzEmptyState` ...). Import another group through its barrel (`../core/core.dart`) and your own part files; import other DOMAIN parts only through the barrel files named in your task, and only after the "ready" line exists (below).

## Gallery (the proof)
- A gallery file `packages/ghazal_testing/lib/src/gallery/<page>_<part>_gallery.dart` and a test `packages/ghazal_testing/test/gallery/<page>_<part>_gallery_test.dart`:
  ```dart
  late GzWorld world;
  void main() {
    setUpAll(() async => world = await GzWorld.load());           // real async, outside testWidgets
    gzGalleryShots(page: 'client', wrap: gzStoryWrap, sections: () => [
      GzGallerySection('brief', (context) => ..., number: 1),       // title = the web data-gz-section id, number = its place on the web page
    ]);
  }
  ```
  Specimens use real objects from `world.repos('reem').venues...` (personas `guest`, `new_client`, `reem`, `hotel_manager`, `hotel_admin`, `provider`; a partner persona needs `venueId` / `providerId`), never hand-built models. Same specimens, states and sample text as the web gallery section (read its `*Sections.tsx`). Section ids and numbers: `node -e "const i=require('./design/.shots/ref/galleries/index.json');for(const e of i.filter(x=>x.page==='client'&&x.lang==='en')[0].items)console.log(e.n,e.title)"`.
- Render and score: `cd packages/ghazal_testing && node ../../tools/with-slot.mjs flutter-test -- flutter test test/gallery/<file>` then from the root `node tools/parity/parity.mjs --gallery <page> --sections 1,2,3` (your numbers). Read the composite PNG of every section in Arabic (`packages/ghazal_testing/build/gallery-parity/<page>/NN-<id>.ar.png`) and at least the worst in English.
- **Bar.** Below 0.075 is clean; 0.075 to 0.12 is acceptable ONLY when the composite shows thin outlines along text and nothing else (the text baseline noise is documented); a section above 0.12, or any visible box, icon, colour or size difference, is a defect: trace it with `pnpm probe` numbers against `tester.getRect` in a test, fix it, re-score. Do at most two fix rounds per section, then report what remains and why. Section height (`dH` column) must be within 4 px unless explained.

## Tests (widget tests, no golden files)
`packages/ghazal_ui/test/<group>/<part>_test.dart`: per component the states that carry logic (selected / compared / favourite toggles call back and flip, disabled does not fire, the guest-locked price shows the lock, countdown states at fixed times), Semantics (one node, label and value), RTL (a start/end placement flips, numbers stay LTR), reduced motion (no transform), 44 dp target. Wrap in `GzHost` / `GzTheme`. Run through `node tools/with-slot.mjs flutter-test -- flutter test <path>` from the package folder (never several `flutter test` by hand in parallel).

## Ownership and coordination
- You may create or edit only: your component files in `packages/ghazal_ui/lib/src/<group>/` (named in your task), YOUR part barrel (`<group>_<part>.dart`: add one `export` per public file), your l10n part pair in `packages/ghazal_ui/l10n_src/`, your tests under `packages/ghazal_ui/test/<group>/`, your gallery files in `packages/ghazal_testing/`, and append-only lines to `docs/engineering/requests.md` (shell `>>`). The group barrels (`client.dart`, ...) already export every part barrel: do not edit them.
- Ready markers. A component other agents wait for is announced the moment it compiles and has a passing test: `echo "- <GzFoo> <path> <date-time>" >> docs/engineering/phase-c-ready.md`. If you need a component of another agent (listed in your task) and its line is not there, build your other components first; when you get to it wait with `until grep -q 'GzFoo' docs/engineering/phase-c-ready.md; do sleep 20; done` (one Bash call, timeout 600000, at most three calls). If it still is not there, write your component against the web signature, mark the gap in your report as BLOCKED, and finish everything else.
- Another agent's half-written files can break `flutter analyze` for a moment: retry once after 60 s before concluding anything; never edit a file you do not own. `pnpm l10n:ui` can fail on another agent's half-written l10n pair: wait 60 s and retry.
- Need a token, a foundation change or a dependency: append one line to `docs/engineering/requests.md` and use the closest existing value; never inline a colour, never `pub add`.

## Done means (run, read the output, report it)
While you work, analyze and check only your own paths (`flutter analyze packages/ghazal_ui/lib/src/<group> packages/ghazal_ui/test/<group> packages/ghazal_testing/lib/src/gallery/<your files>`, `bash tools/check-dart-rules.sh <your paths>`): the other agents are mid-edit. At the end run the root `flutter analyze` and `bash tools/check-dart-rules.sh` once (if either is red only because of another agent's file, say which file). Required: your widget tests and your gallery test green, `pnpm l10n:ui` clean, the parity table for your sections with the composites read. No simulator, no `flutter run`, no `flutter build`.
